Transaction Lifecycle Model

How the model-based tests think about a card transaction on the switch. Each box is a state the test checks; each arrow is an action it sends to the switch. GraphWalker picks the next arrow at random among those whose condition is true, so the same rules get exercised in thousands of orders.

Click a state to see everything that can happen there. Not drawn: every state except Ready returns to Ready with Next transaction.

The three things the model remembers

hostA
Status of host-a, the primary issuer for Visa: up, down or timeout.
hostC
Status of host-c, the backup processor: up or down.
approvedBy
Which host approved the transaction being followed. Reversals go back to that host.

Conditions on the arrows are built only from these three. Everything else (every transaction's status, settlement totals) is tracked by the Java oracle and checked against the switch in every state.
